# Relay operations (self-hosted)

## Environment

| Variable | Default | Meaning |
|---|---|---|
| `ANCHOR_RELAY_DB` | `./data/relay.sqlite3` | SQLite path. Use persistent storage. |
| `ANCHOR_ALLOWED_ORIGINS` | localhost dev origins | Comma-separated exact CORS origins. Never use `*` for a production private-memory service. |
| `ANCHOR_MAX_CIPHERTEXT_BYTES` | 1 MiB | Max decoded ciphertext for one change. |
| `ANCHOR_MAX_VAULT_BYTES` | 50 MiB | Per-vault buffered ciphertext quota. |
| `ANCHOR_ADMIN_TOKEN` | unset | Enables explicit destructive `POST /v1/admin/rooms/{vault_id}/purge`; keep it secret and do not place it in browser code. |

Expose `/healthz` for liveness and `/readyz` for readiness. These reveal no user records. The OpenAPI UI is disabled by default.

## Deployment requirements

- Run behind a maintained HTTPS reverse proxy or TLS-enabled ingress. Do not expose plain HTTP over the public internet. Enforce request-body caps, header/read timeouts, connection limits and slow-client protections at the proxy, in addition to the application body cap.
- Pin a specific container/image digest in production rather than `latest`; scan and rebuild dependencies.
- Persist `/data`, restrict filesystem permissions and encrypt server volumes/backups at the infrastructure layer.
- Do not mount broad host paths into the relay container. Run with non-root UID as the Dockerfile does.
- Set firewall rules so only the public proxy can reach the app container.
- Keep logs free of Authorization headers, request bodies, ciphertext and personally identifying payload metadata. Configure reverse-proxy access logs accordingly.
- The current rate limiter is process-local and SQLite-backed; use a single worker for the starter. For a multi-worker deployment, add shared rate-limiting/queue infrastructure and run load tests. The app body cap consumes and buffers each accepted request up to its configured maximum, so set stricter edge limits appropriate for your deployment.
- Monitor disk use, 4xx/5xx rate, request latency and quota errors without logging vault content. Add alerts for storage near capacity and backup failures.
- Back up SQLite using a consistent SQLite backup mechanism; test restoration. Backups contain ciphertext plus metadata and need access control and retention.
- There is no automated retention/compaction in this version. An optional operator purge exists only when `ANCHOR_ADMIN_TOKEN` is configured. Define retention with the product owner before taking real users. Do not delete old relay changes merely based on age: a device offline for a long time may not have received them.

## Local smoke test

```bash
curl http://localhost:8080/healthz
curl http://localhost:8080/readyz
```

Test using opaque generated bytes only. Never put real user plaintext into relay tests, logs or bug reports.
